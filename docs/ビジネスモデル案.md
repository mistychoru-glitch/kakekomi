## 0. 一言で

> お金に困った人が、**ひとりで抱え込む前に・誰かに話す前に**、匿名で状況を整理し、
> **「どこに電話すれば何をしてくれるか」まで分かった状態で窓口に行ける**ようにする。

売ることよりも先に、**「困った人が、最短で、正しい窓口にたどり着き、その後に行動が続く輪」**を作る。
お金（マネタイズ）は、その輪の中で、直接メリットを得る人から後で受け取る。

## 1. 解く課題と、変えたい行動

| 今 | Kakekomiで変えたいこと |
|---|---|
| 困っても誰にも言えず、相談が遅れる（督促が来てから、期限が過ぎてから） | 督促が届いた**その日**に、匿名で状況を整理できる |
| 窓口の連絡先は調べれば出てくるが、「電話したら何をされるか分からず」動けない | 「かけると何をしてくれるか」付きで案内され、**電話の心理的ハードルが下がる** |
| 窓口に行っても、一から状況を説明するため時間がかかり、聞き漏れも出る | 整理した**要約を持って行ける**（書き出し機能）。窓口は初回の聞き取りを短くできる？ |

最初の対象は**個人の家賃・借金**。事業者の資金繰りも、同じ仕組みで対応できるようにする（後述の§9）。

## 2. 「最短距離」: 困った人は、どこでKakekomiに出会うか

メンターの指摘:「その人がアプリにつく前に、いろんな人に相談して、最終的にたどり着いたのでは遅い。**すぐにアプリにたどり着ける最短距離**は何か」

| 出会う場所（仮説） | 理由 |
|---|---|
| **窓口の入り口**（自治体の自立相談支援機関・社協・法テラス・商工会議所のHP、チラシのQR） | 困った人が最初に「調べる/訪ねる」場所。ここに置かれるのが最短 |
| 督促状・通知を受け取った直後の検索（「家賃 滞納 どうすれば」など） | 一番切迫している瞬間 |
| 士業（弁護士・司法書士・FP）の事務所のサイト・予約画面 | 相談前の事前整理として案内してもらう |
| 家族・友人からの紹介 | 本人が言い出せないとき、周りの人が先に気づくことが多い？ |

→ 共通点は、**本人が信頼している「誰か（窓口・専門家）」が、先にKakekomiを案内する**こと。
広告やインフルエンサーで広げるのではなく、**信頼できる窓口が勧めてくれる構造**を作る。

## 3. ステークホルダーと、それぞれの利得・懸念（仮説）

| 関係者 | 何を得るか | 何を懸念するか |
|---|---|---|
| **困っている本人** | 匿名で整理・次の一歩・窓口の案内。無料 | 個人情報の漏れ、AIの誤り、結局どこに行けばいいか分からない |
| **家族・友人** | 本人に勧めやすい、自分も整理できる | プライバシー |
| **自立相談支援機関・福祉事務所（自治体・社協）** | 初回相談の前に状況が整理されている。聞き取り時間の短縮、聞き漏れの減少？ | 個人情報、AIが誤った案内をしないか、自治体の導入手続き（調達・予算） |
| **法テラス・弁護士・司法書士** | 相談の前に、争点・金額・期限が整理された人が来る | **非弁行為・紹介料の規制**（§7）、AIの出力への責任 |
| **FP・家計相談** | 家計の整理が済んだ状態で来る | — |
| **商工会議所・よろず支援拠点・信金・公庫**（事業者向け） | 資金繰りの整理が済んだ相談者 | 融資の斡旋と受け取られること |
| **家主・管理会社・保証会社** | 滞納が長期化する前に、本人が動く | — |
| **支援NPO** | 相談前の整理を、手を取られず提供できる | — |
| **Anthropic（AI事業者）** | — | 入力がAPIで処理される（Kakekomi側では保存しない） |

## 4. 循環（輪）

```
困った人がKakekomiで整理する（匿名・無料）
        ↓
要約を持って、窓口・専門家に相談に行く
        ↓
窓口は初回の聞き取りが短くなる・聞き漏れが減る？
        ↓
制度や専門家につながり、解決に進む（「うまくいった」が窓口に残る）
        ↓
窓口が「先にKakekomiで整理してきてください」と案内する
        ↓
案内する窓口が増える → より多くの困った人が、最短で整理にたどり着く
```

この輪が回れば、利用が増える理由は「広告」ではなく**「窓口がラクになるから勧める」**になる。
輪の**どこで、誰からお金をもらうのが自然か**を、§6で考える。

## 5. 広がり方の仮説（インフルエンサー以外）

1. **1か所の窓口で、「使ってもらえた」実績を作る**（弁護士の知人の事務所、地域の社協など）
2. その窓口の担当者が、同じ立場の人に紹介する（窓口同士の横のつながり）
3. 自治体の他部署・近隣自治体、士業の団体へ
4. 窓口側に「導入したことで何が変わったか」の数字（聞き取り時間など）がたまれば、導入の根拠になる

「風が吹けば桶屋が儲かる」の最初の一吹きは、**信頼できる1人の専門家が、実際に使って「良かった」と言うこと**。

## 6. お金の話: どこから、何に対して受け取るか

**現状の結論: 収益の形は、まだ決めない（決められない）。**
理由は3つ。
1. 困っている**本人**から取るのは、支払い意欲が低く、信頼も損ねやすい。**本人は無料**が前提（メンターも、課金より課題の解決が先、と助言）
2. 「窓口・専門家」が対価を払うかは、**実際に聞いてみないと分からない**（今は仮説）
3. 紹介料のような形は、**法的に危ない可能性が高い**（§7）

### 候補の比較

| 案 | 誰が払う | 何の対価 | 良い点 | 懸念 |
|---|---|---|---|---|
| A. 窓口向けの導入料（定額） | 自治体・社協・商工会議所・士業事務所 | 事前整理ツールの利用、書き出しの提供 | 輪の中で直接メリットを得る側。本人は無料のまま | 自治体は調達・予算が遅い。効果の証明が必要 |
| B. 助成・補助金・協賛・寄付 | 財団、自治体の補助事業、企業の協賛 | 社会的な価値（孤立・困窮の予防） | 営利色が薄く信頼されやすい。本人は無料 | 継続性が不安定。申請の手間 |
| C. 企業の福利厚生 | 従業員の悩みに備える企業 | 従業員向けの匿名の相談入口。会社には**利用の統計だけ**（内容は見えない） | 法人は払う習慣がある | 内容を企業が見られないことの説明。営業が必要 |
| D. 個人の月額課金 | 本人 | 利用量の拡大（トークン数） | 仕組みが簡単 | 困窮者から取る矛盾。利用量が少ない人は払わない。**今は従属的な位置づけ** |
| E. 士業・金融機関からの紹介料・成功報酬 | 弁護士・金融機関など | 見込み客の紹介 | 収益化しやすい | **弁護士法・弁護士職務基本規程に抵触する恐れ（要確認）**。利益相反（融資への誘導）。信頼を失う。**採らない方向** |

### 現時点の方針案

- **本人は恒久的に無料**。収益のために、本人を特定の窓口や商品へ誘導しない
- 当面は **B（助成・協賛）で小さく回しながら、A（窓口向け導入料）の有料化が成り立つか検証**する
- トークン数の課金（D）は、**コストを守る上限**としてだけ使う（現状は全体の1日上限で対応）
- **E（紹介料）は採らない**。やるなら、必ず法的な確認のあとで

→ 「どのマネタイズが良いか分からない」のは、今は**正常**。確かめる順番は、§8。

### 原価の目安（仮）

- AIの利用料は、開発・テスト期間全体で約0.18ドル（10/6時点）。1回の相談あたりの原価は**数円程度**と見込む（検証前）。Web検索を伴うと上がる
- インフラはCloudflareの無料枠内。つまり、**小さく始めるための固定費はほぼゼロ**

## 7. 法的に確認すべき点（弁護士への確認事項）

以下は作成者の理解であり、**正確性は未確認**。**知人の弁護士に確認できる**環境があり、これを最初の検証として行う。

1. **弁護士法72条（非弁行為）**: 「債務整理の方法を整理して提示する」ことは、法律事務に当たらないか。どこまでが「情報提供」で、どこからが「法律事務」か。Kakekomiが「診断や断定をしない」としている線引きは妥当か
2. **弁護士・司法書士の紹介と対価**: 紹介料・成功報酬・掲載料は、**どの形なら適法か/違法か**（弁護士法27条、弁護士職務基本規程の非弁提携・紹介料の禁止など）。「月額の掲載料」「事務所のHPに設置する利用料」はどうか
3. **個人情報保護法**: 会話の内容を、米国のAI事業者（Anthropic）のAPIに送信することの、利用者への説明（現在は初回の同意画面に明記）で足りるか。越境移転の観点
4. **免責表示の十分性**: 現在の免責（「法律・税務の助言ではない」）の文言で、利用者の誤解を防げるか
5. **融資の案内**: 公庫の事業資金相談ダイヤルなど、公的な窓口を案内することに、規制上の問題はないか。民間の貸金業者を案内する場合は
6. **自治体・社協との連携**: 窓口に置いてもらう際に、必要な手続き・契約・責任分担

## 9. 事業者向け（資金繰り）の位置づけ

- **同じ仕組み**で対応する。窓口が変わるだけ（自立相談支援機関 → 商工会議所・よろず支援拠点・日本政策金融公庫の事業資金相談ダイヤル）
- 状況の読み取り項目（資金の見通し、差し迫った期限、売上の傾向など）は実装済み。**ルール（次の一歩）は簡易版**（給与支払いが迫るときの資金繰り表の整理、無料の経営相談窓口への案内）
- 最初から広げず、**個人で輪が回るかを確認してから**、事業者向けを厚くする（制度が違い、確認すべき専門家も別になる）

## 11. リスク

| リスク | 対策 |
|---|---|
| AIの誤った案内で、利用者に不利益が出る | 窓口の番号は確認済みの一覧に限定。免責表示。誤りの検証（H5）。重大なものは「必ず窓口に確認」と案内 |
| 非弁行為・紹介料に当たる | §7の確認が済むまで、紹介料・成功報酬は採らない。「診断・断定をしない」設計を維持 |
| 個人情報・機密 | 会話はサーバーに保存しない。入力がAI事業者に送られることを明記 |
| 窓口が導入してくれない | 1か所の実績（H1〜H3）を先に作る。導入の手間を小さくする（QRとURLだけで使える） |
| 悪用・料金の暴走 | 回数制限、1日の上限、Anthropic側の残高制（実装済み） |
| 事業の継続性（運営者が1人） | 本資料の方針に沿って、まず検証。エンジニア・福祉に詳しい共同創業者の検討は、検証の結果を見てから |
| 命に関わる相談 | 危険信号は、AIを呼ばず固定の案内を最優先（実装・テスト済み） |

## 12. 発表で言えること（たたき台）

- **解いている課題**: お金に困った人が、誰にも言えず、相談が遅れる
- **アプローチ**: 匿名・保存しない・「かけると何をしてくれるか」まで案内
- **やったこと**: 実際に動くものを公開（URL）。危険信号の検知、確認済みの窓口の案内、要約の書き出し、安全設計（回数制限・保存しない）
- **まだ分からないこと**: 誰が対価を払うか、法的な線引き。**それを確かめる計画**がある（§7・§8）
- **次の一歩**: 知人の弁護士への確認と、窓口へのヒアリング
