# Kakekomi 要件定義書

最終更新: 2026-10-06 ／ 状態: 卒業制作（MVP）として公開中
公開URL: https://kakekomi-worker.misty-choru.workers.dev

## 1. 目的と背景

お金のことで困っている人は、「誰にも言えないまま一人で抱え込む」ことで、相談が遅れ、状況が悪化しやすい。
窓口の連絡先を並べるだけでは、「電話したらどうなるか分からない」という不安から行動できないことも多い。

Kakekomiは、困っている人が**匿名で、安心して、今の状況を整理し、「次に何をすればいいか」と
「かけるとどうなるか」まで分かる**状態にすることを目的とする。窓口へ送るだけの「送客」ではなく、
気持ちを受け止めながら整理する「伴走」を目指す。

## 2. 対象ユーザー

| 区分 | 例 |
|---|---|
| 個人（主対象） | 家賃を滞納している、借金の返済が苦しい、収入が減った |
| 事業者（簡易対応） | 個人事業主・小規模事業者で、給与支払いや資金繰りが厳しい |
| 相談窓口の担当者（将来） | 自治体・社協・士業・商工会議所。相談前の整理ツールとして |

## 3. スコープ

### やる（現在の実装）

- AIとの相談チャット（家賃・借金・事業の資金繰りを中心に、お金の相談全般を受け止める）
- 会話からの状況整理（状況カード）と、次の一歩の提示
- 確認済みの相談窓口の案内（「かけると何をしてくれるか」つき）
- 危険信号（希死念慮など）の無条件の検知と、固定の案内
- 相談内容の要約の書き出し（Markdownファイル）
- アカウント（メール＋パスワード、リカバリーコードによる再設定）
- 乱用対策（回数制限、1日の利用上限、入力制限）

### やらない（今後の課題として扱う）

- 会話内容のサーバー保存（意図的にやらない。後述の方針）
- 決済・課金、トークン数ベースの利用制限
- 管理者向けの画面、匿名投稿の共有機能
- 収入減・税や保険料の滞納などのルールの拡充、全自治体の制度データ
- メール送信（実在確認・メールでの再設定）、SSO
- 法律相談・診断・断定的な助言（行わない。免責を表示）

## 4. 設計方針（意思決定の記録）

| 方針 | 理由 |
|---|---|
| 会話内容をサーバーに保存しない | 金銭・生活の悩みは機密性が高く、保管はリスクが大きい。保存を課金の軸にすることも、利用者・運営の双方にとって好ましくない。学校の卒業制作のレギュレーションにも沿う（アカウント情報のみ保管） |
| 判断ロジックはコード、AIは言い回し | 優先順位・危険信号・窓口の番号を、AIの気まぐれに委ねない |
| 危険信号は最優先・無条件 | 命に関わるため。AIを呼ばず固定応答を返し、回数制限よりも先に判定 |
| AIが案内する電話番号は確認済みの一覧に限定する | 誤った番号は、困っている人を傷つけるため。AIへの指示による限定で、コードで強制してはいない（出力の目視確認が必要） |
| 範囲を「お金の相談」に絞る | 汎用AIとして悪用されると、料金が暴走するため |
| 課金はトークン数（利用量）を軸にする（将来） | 保存容量は差別化にならず、機密情報を持つリスクを伴うため |

## 5. 機能要件

| ID | 要件 | 状態 |
|---|---|---|
| F-01 | 自由記述で相談でき、AIが共感 → 要点 → 次の一歩の順で短く返す | 実装済 |
| F-02 | 会話から状況（相談の種類・緊急度・家賃・エリア・収入・家族・通知と期限など）を読み取り、状況カードに表示する | 実装済 |
| F-03 | 状況に応じた「次の一歩」を、注意点つきで提示する（心理状態がパニック寄りなら1つ、そうでなければ最大3つ。提示済みは重複させない） | 実装済 |
| F-04 | 危険信号の言い回しを検知したら、AIを呼ばずに窓口の固定案内を返す | 実装済 |
| F-05 | 相談窓口の一覧を画面に表示し、AIは一覧にある番号だけを案内する | 実装済 |
| F-06 | 家賃相場・エリア比較など最新の情報が要るとき、AIがWeb検索で根拠を確認する（1返信につき最大3回） | 実装済 |
| F-07 | お金と無関係な依頼（画像生成、プログラミング、雑談など）は丁寧に断る。住居費の相談は応じる | 実装済 |
| F-08 | 会話をAIが要約し、Markdownファイルとして書き出せる | 実装済 |
| F-09 | メールアドレス＋パスワードで新規登録・ログイン・ログアウトできる | 実装済 |
| F-10 | 登録時にリカバリーコードを1回だけ表示し、忘れたときはメール＋コードでパスワードを再設定できる | 実装済 |
| F-11 | 初回に免責・データの扱いを表示し、同意するまで進めない | 実装済 |
| F-12 | 「新しい相談」で、ブラウザ内の会話と状況を消せる | 実装済 |
| F-13 | 開発者アカウントでログインできる（IDとパスワードはサーバーの秘密設定で保持） | 実装済 |

### 次の一歩のルール（`worker/src/rules.ts`）

| テーマ | ルール（提示する次の一歩） |
|---|---|
| 住まい・家賃 | 通知の種類の確認 / 裁判・強制執行の段階なら至急の専門家相談 / 生活保護が難しいときの住居確保給付金 / 就学援助 / 家賃減額・住み替え / 転居費用の補助 / **基本: 自立相談支援機関への相談** |
| 借金・返済 | 取り立ての法規制の説明 / 任意整理・個人再生・自己破産のメリット・デメリット比較 / 別の窓口の提案 / 信用情報開示の限界の説明 / **基本: 法テラスへの相談** |
| 事業（簡易） | 給与支払いが迫るときの資金繰り表の整理と緊急融資の確認 / 無料の経営相談窓口への案内 |

## 6. 非機能要件

### 6.1 プライバシー

- 会話・状況カードはブラウザのlocalStorageにのみ保持し、サーバー（D1）には書き込まない。
- サーバーが保管するのは、メールアドレス、表示名、パスワードのハッシュ、リカバリーコードのハッシュ、セッション、回数制限のカウンターのみ。
- 回答生成のため、入力内容はAI事業者（Anthropic社）のAPIに送信される。この旨は初回の同意画面に明記する。AI事業者側での取り扱いは、同社の規約に従う。

### 6.2 セキュリティ

| 項目 | 対応 |
|---|---|
| パスワード | 8〜128文字、英字と数字の両方を必須。PBKDF2-SHA256（10万回、ランダムソルト）でハッシュ化 |
| リカバリーコード | 16文字（紛らわしい文字を除く32種）。ハッシュのみ保存。使用すると失効し、新しいコードを発行。再設定時は全セッションを失効 |
| セッション | 推測できないランダムなトークン、有効期限30日、ログアウトでサーバー側からも削除 |
| 総当たり対策 | ログイン・登録・再設定のIPごとの回数制限、再設定はアカウントごとにも8回失敗でロック（1時間） |
| 通信 | HTTPS（Cloudflare）、同一オリジンのみCORS許可、セキュリティヘッダー（X-Frame-Options など） |
| 入力 | SQLは全てバインド変数。画面へ出す文字列は全てエスケープ。AIの出力から取り込む値は型・長さ・選択肢を検証。クライアントから届く履歴・状態は形式と大きさを整えてから使用 |
| 開発者アカウント | IDとパスワードはソースに書かず、秘密設定で保持。定数時間で比較 |
| 秘密情報 | APIキー等はGit管理外（`.dev.vars`）とCloudflareの秘密設定のみ |

### 6.3 乱用・コスト対策（無料枠を前提）

回数の保存先はD1（無料枠: 書き込み1日10万回）。KV（無料枠: 書き込み1日1,000回）は不足するため使わない。
IPv6は前半64ビット（/64）にまとめて数える。

| 対象 | 上限 |
|---|---|
| チャット | 1時間30回／ネットワーク |
| 要約 | 1時間10回／ネットワーク |
| 新規登録 | 1時間5回、累計10件／ネットワーク（形式エラーは数えない） |
| ログイン | 1時間15回／ネットワーク |
| パスワード再設定 | 1時間10回／ネットワーク、アカウントごとに失敗8回でロック |
| AI全体 | 1日300回（`DAILY_AI_LIMIT`）。超えると案内を表示。危険信号の案内は対象外 |
| 入力 | 1メッセージ2,000文字、履歴は直近30件、1件4,000文字まで |
| Anthropic側 | 残高制（自動チャージはオフ）。最悪でも残高分で止まる |

### 6.4 可用性・性能

- 通常の返信は約5秒。Web検索を伴うと10秒を超えることがある（返信中は入力中表示を出す）。
- Workers 無料枠（1日10万リクエスト、1リクエストのCPU時間10ms）に収まる想定。

## 8. API

| メソッド・パス | 内容 |
|---|---|
| `POST /api/chat` | 相談の送信。状況の読み取り → ルール → AI返信。危険信号なら固定応答 |
| `POST /api/summarize` | 会話の要約（書き出し用） |
| `GET /api/resources` | 相談窓口の一覧 |
| `POST /api/register` | 新規登録（リカバリーコードを返す） |
| `POST /api/login` | ログイン |
| `GET /api/me` | ログイン状態の確認 |
| `POST /api/logout` | ログアウト（サーバー側のセッション削除） |
| `POST /api/password-reset` | リカバリーコードによるパスワード再設定 |

### `/api/chat` の処理の流れ

1. 入力の整形（履歴・状態を検証して整える）
2. **危険信号の検知** → 該当すれば固定応答を返して終了（回数制限の対象外）
3. 文字数の確認 → IPごとの回数制限 → AI全体の1日上限
4. AIが発言から状況を読み取る（`update_structured_state`ツールで構造化）→ 検証してマージ
5. ルールで次の一歩を決定（コード側）
6. システムプロンプトを組み立て（役割・トーン・範囲・安全・状況・次の一歩・相談窓口・指示）
7. AIが返信を生成（必要ならWeb検索）→ 装飾記号を除去して返す

|---|---|

## 11. テスト

- 自動テスト38件（`npm test`）: 危険信号の検知（見逃し・誤検知）、状況の検証、相談窓口の一覧、IPv6の集約
- 手動・結合テスト: 登録 → 再設定 → ログイン、並列リクエストでの回数制限の正確さ、1日上限、ブラウザでの画面確認（PC・スマホ幅）

### 受け入れ基準

1. 「死にたい」等の言い回しで、AIを呼ばずに窓口の案内（番号と、かけると何をしてくれるか）が表示される
2. 家賃滞納の相談で、状況カードに家賃・エリア等が出て、次の一歩と窓口が案内される
3. AIが案内する電話番号は、窓口一覧にあるものだけ
4. 画像生成などの依頼は断り、家賃相場の質問には答える
5. 登録 → リカバリーコード表示 → ログアウト → 再設定 → 新パスワードでログインができる
6. 書き出しで、要約入りのMarkdownがダウンロードされる
7. ブラウザを閉じても会話はサーバーに残っていない

## 12. 制約・未確認事項・既知の課題

- **法的な適合性は未確認**: 弁護士法（法律事務の取扱い）、個人情報保護法、士業への紹介の可否などは、事業化の前に専門家への確認が必要。
- AIの回答には誤りが含まれる（数字の取り違えなど）。免責表示と、窓口での確認の案内で補う。
- 状況の読み取りは完全ではない（言い回しによって取り違える）。
- メール未送信のため、メールアドレスの実在確認ができず、リカバリーコードを失くすと再設定できない。
- 回数制限は「同じネットワーク」単位。共有のWi-Fi（学校・会社など）では、利用者同士で上限を共有する。
- 相談窓口の電話番号・受付時間は2026年10月時点の公式情報（法テラス・日本政策金融公庫は各公式ページ、金融庁・よりそい・#いのちSOS・いのちの電話は厚生労働省の案内等）。変更があり得るため、定期的な再確認が必要。危険信号のときの固定案内（`worker/src/safety.ts`）の番号も同様。
- いのちの電話（0570-783-556）は通話料がかかる（毎日10:00〜22:00）。よりそいホットライン・#いのちSOSは24時間・無料。

## 13. 今後の課題

1. トークン数（利用量）に基づく利用制限と課金（ログインの価値づけ）
2. ルールの拡充（収入減、税・保険料の滞納、事業）と、自治体の制度データの整備
3. 相談窓口（自治体・社協・士業・商工会議所）向けの導入形態の検討（ビジネスモデルは別資料）
4. メールによる実在確認・パスワード再設定、SSO
5. 返信のストリーミング表示（待ち時間の短縮）
6. 管理者向けの画面（利用状況の確認。会話内容は見えない設計を維持）
